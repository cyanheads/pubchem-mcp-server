# 0.7.0 — 2026-10-14

## Added

- **`pubchem_search_compounds` `searchType: "assay"`** ([#68](https://github.com/cyanheads/pubchem-mcp-server/issues/68)) — lists the compounds an AID found active, or every compound it tested with `activeOnly: false`, with PubChem's exact count as `totalFound`. New `aid` and `activeOnly` inputs; `missing_aid` and `aid_not_found` errors.
- **`pubchem_get_summary` assay fields** ([#68](https://github.com/cyanheads/pubchem-mcp-server/issues/68)) — `method`, `targets` (first 25) with `targetCount`, `numCompounds`, `numActiveCompounds`, `lastDataChange`.
- **`ghs.classifications`** on `pubchem_get_compound_safety` and `pubchem://compound/{cid}/safety` ([#63](https://github.com/cyanheads/pubchem-mcp-server/issues/63)) — each source's signal word, pictograms, H-codes with ECHA notifier `agreement`, `notifications`, `source`, and `sourceRecord`.
- **`status: "not_classified"`** on the same tool and resource ([#71](https://github.com/cyanheads/pubchem-mcp-server/issues/71)) — every deposited classification is an ECHA Not Classified verdict (CIDs 5793 and 135398658 were `no_ghs_data`). `hasData` is true. Each verdict is a `classifications[]` entry with `notClassified: true` and its notifier counts in `notifications`, under any status.
- **`levels`** on `pubchem_get_compound_details` ATC codes ([#64](https://github.com/cyanheads/pubchem-mcp-server/issues/64)) — WHO levels 1-4, top-down. The primary code now carries its name.
- **`otherTargets`** on `pubchem_get_bioactivity` and `pubchem://compound/{cid}/bioactivity` ([#73](https://github.com/cyanheads/pubchem-mcp-server/issues/73)) — each further target of a multi-target assay with its own `outcome` and `activityValues` (112 of aspirin's 4,071 AIDs).
- **`unprocessed`** on `pubchem_get_compound_details`, `pubchem_get_compound_safety`, `pubchem_get_summary`, and identifier-mode `pubchem_search_compounds`, and **`cappedInputs`** on every tool with a capped input ([#70](https://github.com/cyanheads/pubchem-mcp-server/issues/70)) — IDs past the cap return in input order for a follow-up call; each clamp is reported.

## Changed

- **Over-cap inputs are served at the cap instead of rejected** ([#70](https://github.com/cyanheads/pubchem-mcp-server/issues/70)) — ID batches and page sizes up to 1,000 on the read tools. The caps themselves are unchanged.
- **One 50 s time budget per tool call or resource read** ([#57](https://github.com/cyanheads/pubchem-mcp-server/issues/57)) — every PubChem request shares it, 30 s per attempt, covering the rate-limit wait, response body, and retry backoff. The one retry honors a `Retry-After` of 30 s or less.
- **Error messages carry no request URL or host** ([#57](https://github.com/cyanheads/pubchem-mcp-server/issues/57)) — timeouts and network failures read the same whatever the route. A network failure is `ServiceUnavailable`.
- **HTTP errors name PubChem's fault** ([#59](https://github.com/cyanheads/pubchem-mcp-server/issues/59)) — the parsed fault is in `data.fault` and the message (`PubChem returned HTTP 400: PUGREST.BadRequest: …`), and absent when the body states none.
- **`pubchem_get_bioactivity` target filters** ([#65](https://github.com/cyanheads/pubchem-mcp-server/issues/65)) — `targetGeneId` and `targetAccession` match every Gene ID and accession the compound's assay table ties to the same target, and passing both matches either (a COX-2 filter on aspirin: 46 assays, 10 Active).
- **InChIKeys and protein accessions are uppercased before lookup** ([#67](https://github.com/cyanheads/pubchem-mcp-server/issues/67)) — `pubchem_search_compounds`, `pubchem_search_assays`, `pubchem_get_summary`, `pubchem_get_bioactivity`. A PDB chain ID keeps its chain as given.
- **`pubchem_get_summary` splits comma-joined identifiers** ([#66](https://github.com/cyanheads/pubchem-mcp-server/issues/66)) — one row per trimmed piece, 10 looked up per call. A malformed piece gets an `invalid: true` row and is never sent to PubChem.
- **`pubchem_get_compound_xrefs` orders numeric types** ([#69](https://github.com/cyanheads/pubchem-mcp-server/issues/69)) — `PubMedID` newest first; `GeneID`, `ProteinGI`, `TaxonomyID` ascending. String types keep PubChem's order.
- **Maintenance resync** — `framework-skills/`, `CLAUDE.md`/`AGENTS.md`, and `devcheck.config.json`.

## Fixed

- **CIDs, AIDs, and Gene IDs above 2,147,483,647 fail validation** ([#59](https://github.com/cyanheads/pubchem-mcp-server/issues/59)) — every `cid`/`cids` input and CID resource parameter, `aid` (`pubchem_search_compounds`, `pubchem://assay/{aid}`), and `targetGeneId` now return `-32602`, and a `queryType: "cid"` query fails as `invalid_cid_query`, instead of reaching PubChem, which wraps the ID to a negative one or answers HTTP 400. One such CID in a batch rejects the whole call.
- **`pubchem_get_summary` rejects unusable identifiers** ([#66](https://github.com/cyanheads/pubchem-mcp-server/issues/66)) — all pieces blank, or none a positive integer for assay, gene, or taxonomy, fails `invalid_identifier` instead of returning `found: false` rows. More than 1,000 pieces fails `too_many_identifiers`; a non-integer number, or one above `Number.MAX_SAFE_INTEGER`, fails `-32602`.
- **`pubchem_get_compound_interactions` reports SDQ refusals** ([#62](https://github.com/cyanheads/pubchem-mcp-server/issues/62)) — a 404 page, reCAPTCHA page, or non-SDQ JSON from PubChem's SDQ service fails the `drug-drug` or `target` kind in `failedKinds`, with a notice that a retry will not help, instead of reading as zero records.

## Migration

For consumers that validate output strictly or depend on ordering:

- **`pubchem_get_bioactivity`** — for an assay naming several targets, `targetAccession`, `targetGeneId`, `outcome`, and `activityValues` describe the target the filter matched, else the first; `outcomeFilter` reads that outcome and the rest are in `otherTargets`. `activeCount` and `inactiveCount` count by the first target. `filteredCount` and `targetFilter` cover the expanded identifier set.
- **Safety tool and resource** — `ghs.classifications` is a new required field. `signalWord` is the most severe across sources and `source` joins every contributing source with `"; "`. `status` gains `not_classified`, and `withDataCount` includes it. `results` cover looked-up CIDs only.
- **`pubchem_get_compound_details`** — `classification.atcCodes[]` gain a required `levels`, and `description` is filled where PubChem lists the primary code bare.
- **`pubchem_get_compound_xrefs` and `pubchem://compound/{cid}/xrefs`** — numeric types are re-sorted, so an `offset` returns different IDs than before. The resource's 25 PubMed IDs are the highest.
- **`pubchem_get_summary`** — `identifiers` is advertised as strings only (integers are still repaired). Assay, gene, and taxonomy `identifier` echo as numbers, and `requestedCount` counts pieces.
- **Errors** — `data.fault` is the fault PubChem states, where it used to fall back to a 300-character body snippet.
- **Time budget** — a response slower than 30 s per attempt, or a call past 50 s, now fails `Timeout`; a 503 with `Retry-After` over 30 s fails at once.
