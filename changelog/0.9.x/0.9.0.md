# 0.9.0 — 2026-11-24

## Added

- **`searchType: "mass"`** ([#98](https://github.com/cyanheads/pubchem-mcp-server/issues/98)) — `pubchem_search_compounds` lists compounds whose `massType` (`monoisotopic_mass`, `exact_mass`, or `molecular_weight`) lies in an inclusive `massMin`/`massMax` window. Pages to PubChem's 1,000,000-match count (`totalFoundAtLeast` past it); fails with `missing_mass_args`, `inverted_mass_window`, or `mass_search_timeout`. `exact_mass` differs from `monoisotopic_mass` for Cl- and Br-rich compounds and molecules of about 90 or more carbons.
- **`similarity` on similarity hits** ([#97](https://github.com/cyanheads/pubchem-mcp-server/issues/97)) — each hit carries its Tanimoto score (0 to 1, three decimals) from PubChem's 881-bit `Fingerprint2D`, read with the page's property request: one extra request per page when `properties` is not set, plus one for a SMILES query's own fingerprint. Only PubChem's canonical base64 `Fingerprint2D` is scored: a hit without one carries no score, a query without one leaves the page unscored with the reason in the notice, and a query fingerprint out of that layout gets the notice that PubChem returned no query fingerprint. A lookup made only for scoring that fails, PubChem's reply without a property table included, returns the page unscored with a notice to retry.
- **`conformerId`** ([#99](https://github.com/cyanheads/pubchem-mcp-server/issues/99)) — `pubchem_get_compound_3d_structure` fetches a named conformer. The output `conformerId` names the conformer returned on every call, and `alternateConformerIds` never lists it. A malformed ID or another CID's fails as `invalid_conformer_id`, an unknown one as `conformer_not_found`.
- **`activityName` and `sort: "potency"`** ([#102](https://github.com/cyanheads/pubchem-mcp-server/issues/102)) — on `pubchem_get_bioactivity`, `activityName` keeps assays whose reported target has a value with a named measurement (`["IC50"]`, whole names, case-insensitive) and narrows that target's values to the matches; when it removes every assay the other filters kept, the notice lists the names those assays carry. `sort: "potency"` orders the kept assays by lowest kept value, ties to the lower AID, and fails as `missing_activity_name` without `activityName`.
- **`comment` and `sourceId` on assay summaries** ([#100](https://github.com/cyanheads/pubchem-mcp-server/issues/100)) — `pubchem_get_summary` returns the depositor's comment (Active threshold, citation) and own assay ID. A comment, or an assay description, of only blank lines is omitted.

## Changed

- **BREAKING: `classification.meshClasses[]`** ([#95](https://github.com/cyanheads/pubchem-mcp-server/issues/95)) — elements of `pubchem_get_compound_details` change from strings (scope notes) to `{ name, description }`, the MeSH heading and its scope note. Read `.description` where the string was read.
- **`Title` in the default property set** ([#101](https://github.com/cyanheads/pubchem-mcp-server/issues/101)) — `pubchem_get_compound_details` and `pubchem://compound/{cid}` now return it (a core set of 15). A record PubChem gives no Title has no `Title` key.
- **Server `instructions`** — name the mass range search.
- **Vitest under Bun** — runs the threads pool, since 5.1.1's forks pool hangs there; its module cache under `node_modules/` stays out of the `.mcpb` bundle.

## Fixed

- **`pubchem_get_compound_interactions` for a CID PubChem has no record of** ([#96](https://github.com/cyanheads/pubchem-mcp-server/issues/96)) — with `drug-food` requested, the notice says so and points at `pubchem_search_compounds`; an empty page with no drug-food answer (target-only, drug-drug-only, or both) adds a verify-the-CID hint. The notice appears only when no requested kind returned entries.
- **`pubchem_get_compound_details` `found`** — a real compound holding none of the requested properties (`properties: ["Title"]` on CID 130000000) read `found: false`; it now reads `found: true` with an empty `properties` record.
- **Property replies without a table** — a reply with no property table failed `properties` hydration, `pubchem_get_compound_details`, and `pubchem://compound/{cid}` as an internal error; it now fails as ServiceUnavailable after one retry, as does a reply holding a row that is not an object.
