# 0.8.0 — 2026-10-28

## Added

- **`pubchem-guide` agent skill** — `skills/pubchem-guide/SKILL.md` covers salt vs parent CIDs, where Gene IDs and accessions come from, why gene-symbol, Gene ID, and accession searches disagree, and how to read activity, potency, and GHS data. The server serves it through `createApp({ skills: 'skills' })`: `skill://pubchem-guide/SKILL.md` joins `resources/list` and the `skill://{+path}` template resolves it. It also ships in the npm package, Docker image, `.mcpb` bundle, and plugin installs.
- **Root `plugin.json` + `mcp.json`** — the Agent Plugins 1.0.0 root pair.

## Changed

- **Caller text in notices and error messages** — stored as sent and escaped when `content[]` renders it, so `structuredContent.notice` and error messages carry it exactly as the caller wrote it (still cut to 100 characters).
- **`content[]` rendering under mcp-ts-core ^0.13.18** — error text is Markdown-escaped, enrichment trailer values render as code spans, and notices are quoted on every line. `format()` output is unchanged.
- **`pubchem_get_bioactivity` `targetGeneId` and `targetAccession` descriptions** ([#85](https://github.com/cyanheads/pubchem-mcp-server/issues/85)) — name the sources that yield each identifier. Gene IDs: the `GeneID:N` in a `pubchem_get_compound_interactions` target entry's `partner`, or the `targetGeneId` of a result without a target filter. Accessions: an assay's `targets` in `pubchem_get_summary`, the `accession:X` in a target entry's `partner`, or the `targetAccession` of a result without a target filter. Both had pointed at `pubchem_search_assays`, which returns AIDs only.
- **`pubchem_search_assays` no-match notice** ([#85](https://github.com/cyanheads/pubchem-mcp-server/issues/85)) — says `genesymbol` takes the official symbol (`PTGS2`, not `COX-2`) instead of pointing at `pubchem_get_summary`.
- **`pubchem_search_assays` `targetType` description** ([#86](https://github.com/cyanheads/pubchem-mcp-server/issues/86)) — `genesymbol` matches across species, and `geneid` and `proteinaccession` return overlapping, different sets for one protein, so a complete list unions both.
- **`.mcpb` bundles** — no longer carry the framework's build-only files or dev paths; the SDK's `dist/ext/skills/` runtime stays in (local port of [cyanheads/mcp-ts-core#794](https://github.com/cyanheads/mcp-ts-core/issues/794)).

## Fixed

- **`pubchem_search_assays` with a `targetQuery` PubChem refuses** ([#81](https://github.com/cyanheads/pubchem-mcp-server/issues/81)) — PubChem answers a `targetQuery` carrying a line break, another C0 control character other than tab and NUL, or DEL with HTTP 400, which now fails as `ValidationError` (-32007) with `reason: "target_query_rejected"` and a recovery hint, carrying PubChem's fault on `data.fault` when it states one. It was an untyped -32602. A tab, NUL, C1 control, U+2028, or U+2029 still returns no match.
- **`pubchem_search_compounds` formula and structure searches** ([#87](https://github.com/cyanheads/pubchem-mcp-server/issues/87)) — an HTTP 400 from PubChem now fails as `search_query_rejected` with its recovery hint, instead of an untyped -32602. PubChem answers a formula carrying a line break, another C0 control character other than tab and NUL, or DEL with one; a formula with NUL still returns no match.
- **`pubchem_get_compound_interactions` retry advice** ([#82](https://github.com/cyanheads/pubchem-mcp-server/issues/82)) — the `failedKinds` notice offers a retry only for failures a retry can clear (rate limit, timeout, network error, unreadable response, 5xx other than 501) and tells the rest that repeating the call fails the same way. A kind failing with HTTP 400, 403, 501, or an unexpected response shape no longer gets retry advice.
- **An aborted PubChem request the caller did not cancel** ([#82](https://github.com/cyanheads/pubchem-mcp-server/issues/82)) — now fails as retryable `ServiceUnavailable` ("PubChem ended the request before answering"), not `RequestCancelled`, so a `pubchem_get_compound_interactions` kind that hits it gets retry advice.
