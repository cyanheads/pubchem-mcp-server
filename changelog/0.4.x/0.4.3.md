# 0.4.3 — 2026-07-28

## Changed

- **`pubchem_get_compound_xrefs`**, **`pubchem_get_summary`**, **`pubchem_get_compound_details`** — `format()` no longer re-slices arrays that `structuredContent` already returns in full; xref IDs, gene/taxonomy synonyms and lineage, and MeSH classes now render completely instead of stopping at 20/10/3 items with a `(+N more)` note. ([#37](https://github.com/cyanheads/pubchem-mcp-server/issues/37))
- **`pubchem_get_compound_details`**, **`pubchem_get_summary`** — MeSH classes render one per line and synonym/lineage/array fields join on `" | "` instead of `"; "`/`", "`, so a value carrying its own comma or semicolon (CAS-inverted names, MeSH scope notes) can't be misread as an entry boundary.
- **Tool and resource descriptions** — removed reader-naming ("the model can reason over"), internal API-call-count framing ("one extra API call", "efficiently batches"), and maintainer shorthand ("mirrors pubchem_*") from `get-compound-3d-structure`, `get-compound-details`, and all 6 resource definitions; `pubchem://compound/{cid}/image` now states its fixed 300x300 output instead of implying tool-equivalent sizing. ([#35](https://github.com/cyanheads/pubchem-mcp-server/issues/35))

## Fixed

- **`pubchem_get_summary`** — assay summaries now read substance counts from `SIDCountAll`/`SIDCountActive` instead of keys PubChem's `assay/aid/{aid}/summary` endpoint never emits (`NumberOfSubstances`, `TotalSIDCount`, `ActiveSidCount`, `ActiveCount`), so `numSubstances`/`numActive` populate instead of silently omitting. ([#39](https://github.com/cyanheads/pubchem-mcp-server/issues/39))
- **`pubchem_get_summary`** — taxonomy summaries now flatten the `RankedLineage` object (most-inclusive-first, blank ranks dropped) into `lineage`, and map the top-level `Synonym` array into `synonyms`; both previously read nonexistent keys (`Lineage`, `ParentTaxList`) and stayed empty. ([#39](https://github.com/cyanheads/pubchem-mcp-server/issues/39))
